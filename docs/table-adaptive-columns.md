# 표 컬럼 자동 합침 · 펼침

목록 표가 좁으면 관련 필드 두 개를 한 칸에 쌓고, 넓으면 각자 컬럼으로 갈라 준다.  
**언제** 갈라질지는 표가 계산한다. 화면마다 px 브레이크포인트나 `COLUMN_LEVELS`를 두지 않는다.

이 문서는 구현 규칙이다. 다른 시스템에도 그대로 옮길 수 있게, 의미와 측정·선언·금지만 적는다.

---

## 1. 한 줄 규칙

> 묶을 수 있는 단위는 **필드 정확히 2개**다.  
> 각 칸의 최소 폭은 **헤더 글자 수**와 **셀 내용 글자 수** 중 큰 값 × **한글 한 자 폭**이다.  
> 표 너비가 그 합보다 작으면 뒤에서부터 다시 한 칸으로 합친다.

---

## 2. 묶음(쌍) 정의

사람이 정하는 것은 “이 두 필드가 한 의미 묶음이다” 한 가지뿐이다.

| 해야 할 일 | 하지 말 것 |
|---|---|
| 주 필드 + 보조 필드 **한 쌍**만 한 칸에 넣는다 | 3개 이상을 한 `CellStack` / 한 헤더에 넣는다 |
| 헤더도 그 두 필드의 라벨만 가진다 | `품목구분·전문분류·단위·포장`처럼 나머지 필드를 한 헤더로 이어 붙인다 |
| 짝이 없는 필드(활성, 관리, 순번)는 혼자 둔다 | 화면마다 `1180px` / `COLUMN_LEVELS[2]` 를 새로 짠다 |

**좋은 쌍 예**

- 이름 + 사번
- 품목명 + 품목명2
- 품목코드 + 약호
- 품목구분 + 전문분류
- 단위 + 포장규격
- 난이도 + 공수
- 제형 + 진행방법
- 포장일 + 완료예정
- 담당자 + 상태
- 2인시험 + 활성

**나쁜 묶음 예**

- 분류 = 품목구분 + 전문분류 + 단위 + 포장규격 (4개 → 헤더와 값이 어긋남)
- 품목 = 품목명 + 코드 + 제조번호 (3개 → 보조줄을 `코드 · 제조번호`로 뭉개지 말고, 품목명은 단독, 코드+제조번호가 한 쌍)

짝을 고르는 기준: 같은 종류의 정보이고, 좁을 때 위·아래로 쌓아도 읽힌다.

## 3. 최소 폭 측정

### 3.1 한글 한 자

표에 실제로 쓰인 폰트로 `"가"` 한 글자의 CSS px를 잰다.  
브라우저 확대(Ctrl +/-)는 CSS 픽셀 폭을 바꾸므로 같은 기준으로 다시 잰다.

### 3.2 글자 수 (자수)

| 문자 | 가중치 |
|---|---|
| 한글, 한자, 전각 | 1 |
| 숫자, 영문, 기호 | 0.5 |
| 제어 문자 | 무시 |

```
자수("포장규격") = 4
자수("EA")      = 1
자수("100ML")   = 2.5
```

### 3.3 한 칸의 최소 폭

```
내용자수 = 보이는 행들 중 그 칸 텍스트의 최대 자수
           (이상치 한두 건에 막히지 않게 상한 12자)
사용자수 = max(헤더자수, 내용자수, 2)   // 빈 칸도 최소 2자
최소폭   = 사용자수 × 한글한글자폭 + 패딩(32px)
```

헤더가 더 길면 헤더를, 값이 더 길면 값을 따른다.

### 3.4 한 쌍을 펼칠 때 / 합칠 때

같은 쌍에 대해

- **합침 폭** = 한 칸. 자수는 `max(묶음헤더, 주내용, 보내용)`
- **펼침 폭** = 주 칸 최소폭 + 보조 칸 최소폭
- **추가 비용** = 펼침 폭 − 합침 폭

고정 칸(순번, 관리, 단독 필드)은 항상 자기 최소 폭을 차지한다.

```
필요폭 = Σ 고정칸 + Σ (펼친 쌍은 펼침폭, 아닌 쌍은 합침폭)
```

표 너비 ≥ 필요폭이면 앞에서부터 쌍을 펼친다.  
이미 펼친 쌍은 한글 2자만큼 더 좁아져야 다시 합친다(깜빡임 방지).

## 4. 화면에 적는 방법

마크업은 **항상 합쳐진 모양**으로 둔다. 펼침 DOM은 `Table`이 만든다.

```tsx
<Table>  {/* layout="fluid" | "content" 기본. wide(캘린더)는 자동 합침 안 함 */}
  <TableHeader>
    <TableRow>
      <TableHead>
        <SortColumnHeader
          col={{
            key: "name",
            label: "품목명",          // 합쳐졌을 때
            fields: [
              { id: "name", label: "품목명" },
              { id: "nameAlt", label: "품목명2" },
            ],
          }}
          ...
        />
      </TableHead>
    </TableRow>
  </TableHeader>
  <TableBody>
    <TableRow>
      <TableCell>
        <CellStack
          primary={row.name}
          secondary={row.nameAlt}
          secondaryLabel="품목명2"   // fields가 2개가 아닐 때만 필요
        />
      </TableCell>
    </TableRow>
  </TableBody>
</Table>
```

### 계약

1. `CellStack`의 `primary` / `secondary`와 헤더 `fields`는 **같은 두 필드**여야 한다.
2. `fields.length === 2`이면 펼쳤을 때 헤더 라벨은 그 두 개다.
3. 정렬 헤더가 한 필드뿐이면 `secondaryLabel`로 보조 헤더를 적는다.
4. `layout="wide"`(가로 스크롤 행렬)와 이미 칸을 직접 그리는 표만 `adaptive={false}`.

### 구현이 하는 일

- 헤더 라벨·셀 텍스트를 모아 3절의 최소 폭을 계산한다.
- 여유가 있는 쌍부터 `th`/`td`를 하나 더 넣는다.
- 창 크기, 사이드바, 브라우저 확대/축소에 다시 계산한다.

## 5. 다른 시스템에 옮길 때

필요한 것은 네 가지다.

1. **쌍 선언**: 주/보조 두 필드 (컴포넌트 이름은 달라도 된다).
2. **한글 한 자 측정**: 표 폰트로 `"가"`의 폭.
3. **자수**: 3.2절 가중치.
4. **탐욕 펼침**: 고정 칸을 빼고, 앞에서부터 추가 비용이 나오면 펼친다. 히스테리시스 2자.

언어·프레임워크에 묶이지 않는다. 이 저장소 구현은

- 측정: `frontend/lib/hangul-width.ts`
- 표 적용: `frontend/components/ui/table.tsx`
- 쌍 마크업: `CellStack` + `SortColumnHeader.fields`

## 6. 이 프로젝트 쌍 목록

새로 화면을 만들 때 아래를 그대로 쓴다. 3필드 묶음은 쓰지 않는다.

| 화면 | 쌍 (주 + 보조) | 단독 |
|---|---|---|
| 품목 마스터 | 품목코드+약호, 품목명+품목명2, 품목구분+전문분류, 단위+포장규격, 난이도+공수 | 상태, 관리 |
| 오더 | 품목코드+제조번호, 제형+진행방법, 포장일+완료예정, 공수+긴급, 담당자+상태 | 확정, 품목명, 관리 |
| 시험항목 | 2인시험+활성 | 시험항목명, 대분류, 예상시간, 관리 |
| 시험자 | 이름+사번, 단독+2인 | 순번, 상태, 관리 |
| 장비 | 장비명+코드, 카테고리+위치, 최근검교정+차기검교정 | 상태, 관리 |
| 사용자 | 사용자명+사번 | 역할, 상태, 마지막 로그인, 관리 |
| 시험현황 / 홈 | 제품명+유형, 시험번호+시험항목, 담당자+수탁사, 접수일+완료예정 | 진행상태, (구분) |
| 안정성 | 품목명+품목코드, 시험종류+기간 | 제조번호, 일자, 상태 |

---

## 7. 확인

- 헤더 이름과 그 아래 값이 같은 필드인가.
- 좁히면 쌍이 한 칸으로 쌓이고, 넓히면 헤더가 두 개로 갈라지는가.
- Ctrl +/- 확대에도 같은 규칙으로 다시 붙는가.
- 한 칸에 점이 찍힌 라벨이 세 개 이상 이어져 있지 않은가.
