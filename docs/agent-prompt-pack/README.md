# 대화형 AI 에이전트 프롬프트 팩 (이식용 / 도메인 중립)

bizday AI 에이전트에서 **도메인 의존 부분(테이블·컬럼·업무규칙·회사 식별자)을 제거하고
범용 골격만** 추출한 프롬프트 모음. 다른 프로젝트에 그대로 복사해서 플레이스홀더만
치환하면 같은 구조의 대화형 에이전트를 만들 수 있다.

## 1. 파이프라인 (이 팩의 핵심 설계)

한 방에 LLM 하나가 다 하는 구조가 아니라, **역할이 분리된 단계**로 흐른다.
각 단계는 앞 단계의 출력만 신뢰하고, 자기 역할 밖의 판단을 하지 않는다.

```
사용자 질문
   │
   ├─[0] 고정 인텐트 매치 ────────► 적중 시 LLM 0회로 즉시 응답 (수십 ms)
   │        (정규식/슬롯, 코드 레벨)
   │
   ├─[1] 의도 분석          01_intent_analysis.txt
   │        chat인가 데이터 질문인가 / 무엇을 조회할 것인가(계획만, 쿼리 아님)
   │        └─ chat 이면 여기서 바로 [4]로
   │
   ├─[2] 쿼리·도구 호출 생성  02_query_generation.txt
   │        [1]의 계획 → 실행 가능한 쿼리 1개 + 출력 계약(JSON)
   │
   ├─[3] 검증 게이트 (코드 레벨, LLM 아님)  06_validation_gate.md
   │        문법·권한·테넌트 경계·금지 구문 → 실패 시 [2] 재시도(피드백 동봉)
   │
   ├─[4] 결과 해석          03_result_interpretation.txt
   │        원시 결과 → 사람이 읽는 설명 + 시각화 타입 결정
   │
   ├─[5] 자연어 답변 렌더    04_natural_answer.txt
   │        Claude/ChatGPT처럼 결론 먼저, 분량은 내용에 비례
   │
   └─[6] 학습 캡처(선택)     05_learning_capture.txt
            확정된 지식/쿼리/인텐트를 태그로 저장 → 다음 턴부터 [0]·[1] 근거로 재사용
```

**왜 나눴는가 (다른 프로젝트에서도 유지할 것)**

| 원칙 | 이유 |
|---|---|
| 분석과 생성을 분리 | 한 프롬프트가 "해석 + 생성 + 보안 + 서식"을 다 하면 하나 고칠 때 나머지가 깨진다 |
| 고정 인텐트 선행 | 반복 질문 대다수는 LLM 없이 끝난다. 실측 27~40s → 0.09s |
| 검증은 LLM이 아닌 코드로 | 보안 경계를 모델 판단에 맡기지 않는다. 모델은 틀리고 코드는 안 틀린다 |
| 렌더링 단계 분리 | 서식 규칙이 추론 프롬프트를 오염시키지 않는다 |
| 근거 우선순위 명시 | 학습 지식이 스키마를 이기지 못하게 |

## 2. 플레이스홀더 (치환 대상)

모든 파일에서 `{{...}}` 는 **프로젝트별 치환**, `{...}` 는 **런타임 주입**이다.

### 프로젝트별 (한 번만 치환)

| 토큰 | 의미 | bizday 예 |
|---|---|---|
| `{{AGENT_NAME}}` | 에이전트 이름 | 데이지 |
| `{{DOMAIN}}` | 업무 도메인 한 줄 | 기업 영업·인사·비용 관리 |
| `{{DATA_SOURCE}}` | 데이터 소스 종류 | MariaDB |
| `{{QUERY_LANG}}` | 생성할 쿼리 언어 | SQL |
| `{{TENANT_KEY}}` | 테넌트 격리 키 (없으면 3장 통째 삭제) | biz_csno |
| `{{LANG}}` | 응답 언어 | 한국어 |

### 런타임 주입 (매 요청 채움)

| 토큰 | 내용 |
|---|---|
| `{today_str}` `{today_year}` `{today_month}` | 날짜 기준 — **반드시 주입**. 없으면 모델이 연도를 하드코딩한다 |
| `{schema}` | 이번 질문에 필요한 스키마/도구 정의만 (전량 아님) |
| `{catalog}` | 전체 목록의 축약 다이제스트 ([1]단계 후보 탐색용) |
| `{few_shot}` | 유사 질문-쿼리 예시 |
| `{learned_rules}` | 승인된 학습 지식 |
| `{memo_block}` | 사용자/조직 메모 (상한 두기) |
| `{plan}` | [1]단계 JSON 출력 그대로 |
| `{question}` `{columns}` `{row_count}` `{data_sample}` | [4]단계 입력 |

> ⚠️ **치환 순서 주의.** `{{AGENT_NAME}}` 같은 프로젝트 토큰은 **로드 직후 문자열 replace 로
> 먼저** 없앤다. 그 다음에 `.format()` 으로 런타임 값을 채운다.
> 프롬프트 안의 JSON 예시 중괄호는 `.format()` 에 먹히지 않도록 `{{ }}` 로 이스케이프돼 있다 —
> 순서를 뒤집으면 JSON 예시가 깨지므로 반드시 replace → format 순으로.
>
> ```python
> tpl = Path("02_query_generation.txt").read_text(encoding="utf-8")
> for k, v in PROJECT_TOKENS.items():      # 1) 프로젝트 토큰 먼저
>     tpl = tpl.replace("{{" + k + "}}", v)
> prompt = tpl.format(**runtime_values)    # 2) 런타임 값 나중
> ```

## 3. 컨텍스트 주입 전략 (성능의 핵심)

실측으로 검증된 규칙 — 그대로 옮길 것.

1. **[1]단계엔 다이제스트, [2]단계엔 원본.**
   [1]은 "무엇이 필요한가"만 고르면 되므로 전체 카탈로그의 **요약**을 준다(45K자 → 22K자).
   [2]는 [1]이 고른 대상의 **원본 스키마만** 받는다. 전체를 주지 않는다.
2. **후보 검색으로 카탈로그를 대체하지 말 것.**
   [1]에 임베딩 top-k 검색 결과만 주면 모델이 "그런 데이터 없다"고 답하는 실패가 생긴다.
   전체 메뉴(축약본)를 보여주고 모델이 고르게 한다.
3. **단순 질문은 [1]을 건너뛰고 [2] 직행.**
   판정 규칙(예: 대상이 명시된 단일 항목 조회)을 코드로 두면 2.2s에 끝난다.
4. **대화 이력은 조건부 주입.**
   "그거/작년은?/부서별로" 같은 참조 표현이 있을 때만 이전 턴을 넣는다.
   항상 넣으면 모델이 이전 주제를 현재 질문에 섞는다.

## 4. 최소 이식 순서

1. `04_natural_answer.txt` + `00_core_agent_system.txt` → 검색·조회 없는 **순수 대화 에이전트**가 바로 동작
2. `01` + `02` + `06` 추가 → 데이터 조회 에이전트
3. `03` 추가 → 결과 해석·차트
4. `05` + 고정 인텐트 → 학습·속도 최적화

## 5. 도구 호출(tool calling) 로 바꾸려면

`02_query_generation.txt` 의 출력 계약을 쿼리 문자열 대신 도구 스키마로 바꾸면 된다.
나머지 단계(1·3·4·5)는 그대로 쓴다. [3] 검증 게이트는 "쿼리 검사" 대신
"도구 인자 검사 + 허용 도구 화이트리스트"가 된다.
