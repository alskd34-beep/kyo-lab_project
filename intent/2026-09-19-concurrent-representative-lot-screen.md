# Intent: 동시분석 대표 로트 변경 화면
Author: 사용자 요청/오케스트레이션 · Status: completed

## Problem
관리자가 동시분석 그룹의 대표 로트를 바꾸려면 현재 대표 표시를 확인하고 변경 결과가 그룹 배정에 미치는 범위를 한 화면에서 판단하기 어렵다. 대표가 바뀌었는지와 어떤 로트가 기준이 되었는지가 오더 목록과 그룹 화면에서 일관되게 드러나지 않는다.

## Proposed outcome
관리자가 동시분석 그룹에서 대표 로트를 확인하고 변경할 수 있으며, 변경된 대표가 그룹의 배정 기준으로 표시된다. 잠금 또는 작업 시작 상태의 오더는 보호되고, 변경 결과와 적용되지 않은 대상의 사유를 관리자에게 알 수 있게 한다.

## Affected users and systems
- 역할: 관리자(대표 로트 변경), 시험자(변경된 대표·배정 결과 확인)
- 화면: AI 스케줄 오더 목록·동시분석 그룹 탭·대표 변경 화면
- 테이블: concurrent_analysis_groups, concurrent_analysis_group_items, pct_orders, pct_order_assignees, qc_jobs, reassignment_history, notifications
- 확정(LOCK)·작업 시작 상태와의 관계: LOCK 또는 시험 시작 오더는 대표 변경에 따른 배정 기준 변경 대상에서 보호한다.
- 크론: `instrumentation.ts` PCT 적재의 자동 그룹 재생성은 잠긴 그룹과 지정된 대표를 보존해야 하며, 대표 변경 화면 자체는 크론을 추가하거나 변경하지 않는다.

## Constraints
관리자 권한과 기존 동시분석 그룹의 LOCK·작업 시작 보호 규칙을 유지한다. 대표 변경은 그룹의 시험 결과·검토·승인 상태를 전파하지 않으며, 기존 담당자 슬롯과 시험항목 배분 규칙을 임의로 바꾸지 않는다. 운영 데이터베이스에 직접 적용하지 않고 현재 스키마와 호환되는 범위에서 동작해야 한다.

## Open questions
- 대표 변경 후 이미 담당자가 있는 미시작·미확정 멤버의 담당자 구성을 자동으로 다시 맞출지, 관리자 확인 후 적용할지 최종 운영 기준이 필요하다.
- 대표 후보에 포장일이 없는 오더가 포함될 때 화면에서 선택을 허용할지 안내만 할지 결정이 필요하다.
