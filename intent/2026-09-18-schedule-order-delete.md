# Intent: AI 스케줄 선택 오더 삭제
Author: 사용자 요청/오케스트레이션 · Status: completed

## Problem
관리자가 AI 스케줄에서 선택한 오더를 한 번에 삭제할 수 없고, 자동 적재 오더는 삭제 대상에서 제외된다. 이미 삭제된 오더·확정(LOCK) 오더·시험 작업이 존재하는 오더가 섞인 경우 처리 가능한 오더와 차단된 오더를 구분해 확인하기 어렵다. 선택 바와 관련 안내 문구의 동시분석 용어도 실제 기능 의미와 일치하지 않는다.

## Proposed outcome
관리자가 선택한 여러 오더에 하나의 필수 삭제 사유를 적용해 처리 가능한 오더를 소프트 삭제할 수 있다. 자동 적재 오더를 삭제해도 다음 제조팀 계획 적재에서 임의로 복구되지 않으며, 처리 결과에 성공 건수와 건너뛴 건수·사유가 표시된다. 관련 사용자 노출 문구는 ‘동시분석 그룹 지정’으로 통일된다.

## Affected users and systems
- 역할: 관리자만 삭제 가능; 시험자는 기존처럼 삭제할 수 없음
- 화면: AI 스케줄 오더 화면(`/schedule/orders`)과 선택 작업 바·삭제 사유 모달
- 테이블: `pct_orders`, `pct_order_edits`, `qc_jobs`, 동시분석 그룹 관련 테이블
- 확정(LOCK)·작업 시작 상태와의 관계: LOCK 오더와 `qc_jobs`가 존재하는 오더는 삭제하지 않으며 선택 묶음의 나머지는 계속 처리
- 크론: `instrumentation.ts`의 PCT 적재가 사용자 삭제 자동 오더를 복구하지 않아야 함

## Constraints
행 삭제 없이 GMP 이력을 보존하고 삭제 사유를 수정 이력에 남긴다. 기존 동시분석 그룹 정리·담당자·시험 작업 보호 규칙을 유지하며 코드 식별자와 DB 값은 변경하지 않는다. 운영 DB에는 직접 적용하지 않고 필요한 스키마 변경은 별도 마이그레이션으로 제공한다.

0056 마이그레이션이 적용되기 전에는 자동 오더 삭제를 안내 메시지로 차단하고, 기존 수동 오더 삭제는 계속 동작해야 한다. 운영 배포는 0056 SQL 선적용 후 앱 배포 순서를 따른다.

## Open questions
- 운영 배포 시 사용자 삭제 표식 마이그레이션 0056을 앱 배포 전에 적용할지 운영 절차에서 확인한다.
- 기존 배포 전에 이미 삭제된 자동 오더는 사용자 삭제 표식이 없으므로, 마이그레이션 적용 시 소급 판정하지 않고 기존 적재 복구 규칙을 유지할지 운영자가 결정해야 한다.
