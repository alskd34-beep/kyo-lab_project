# Intent: 동시분석 그룹은 대표 한 번의 검토·승인으로 그룹 전 배치를 승인완료까지 진행한다
Author: kyo (개발) · Status: completed
승인: 2026-09-15 사용자 사전 승인

## Problem
사용자 요청 원문:
> 작업현황에 동시분석으로 그룹되어 있는 상태는 단계별 진행을 각각 승인이 아니라 대표 그룹 한개를 진행 하면 동일하게 적용 되는 방식으로 변경해서 승인완료까지 가도록 필요함.

동시분석 그룹은 여러 제조번호(배치)를 한 번에 시험하는 묶음이다. 시험자 쪽(할 일 화면)에서는 그룹 카드 하나로
시험항목 시작·완료를 한 번에 누르지만, **관리자 쪽 단계 진행은 전부 배치 하나씩**이다.

- 관리자 작업 현황 패널·시험현황 서랍은 작업이 동시분석 그룹에 속했는지조차 보여 주지 않는다.
  같은 날 같은 장비로 함께 시험한 3배치를 검토하려면 세 작업을 따로 찾아 열어야 한다.
- 같은 시험항목(예: 함량)을 검토 시작 → 검토 완료하는 일을 배치 수만큼 반복한다. 병렬 배정 오더면 담당자별 작업까지 곱해진다.
- 모든 항목 검토가 끝난 뒤 [승인]도 배치마다 따로 눌러야 승인완료가 된다.
- 반복하다 한 배치를 빠뜨리면 그 배치만 검토중·승인전에 남는데, 목록에서 그룹 표시가 없어 알아차리기 어렵다.

## Proposed outcome
- 관리자가 그룹에 속한 작업(배치)을 열면 **같은 그룹의 다른 배치 목록**(QC번호·제조번호·단계·담당자)이 함께 보인다.
  작업 현황 카드와 시험현황 목록에는 그룹 소속임을 알리는 표시가 붙는다.
- 그 패널에서 누르는 **시험항목 검토 시작·검토 완료**, **완료 항목 전체 검토 시작 / 검토 중 항목 전체 검토 완료**,
  **[승인]** 은 기본적으로 **그룹의 모든 배치에 똑같이 적용**된다. 한 배치만 처리하고 싶으면 "이 배치만"을 고를 수 있다.
- 그룹 적용 중 조건이 맞지 않는 배치(아직 시험 중·이미 검토됨·승인완료 등)는 **건너뛰고 나머지를 처리**하며,
  처리한 배치와 건너뛴 배치·사유를 결과로 알려 준다. 처리할 대상이 하나도 없으면 아무것도 바꾸지 않고 알린다.
- 되돌릴 수 없는 그룹 검토 완료·그룹 승인은 누르기 전에 **대상 배치 목록을 확인**받는다.
- 검토 기록·단계 이력은 지금처럼 **배치(작업)·시험항목마다 따로** 남는다. 묶이는 것은 관리자의 조작뿐이다.
- 검토 취소·재실시·관리자 직접 변경은 배치별 사정·사유가 다른 정정이라 지금처럼 배치 하나씩 한다.

## Affected users and systems
- 역할: **관리자**(그룹 검토·그룹 승인·그룹 표시). 시험자는 바뀌지 않는다(할 일 화면의 그룹 시험 조작 그대로, 검토·승인 권한 없음).
- 화면: `/product-test/prod-status`(작업자 작업 현황 — 레인 카드 표시, 오른쪽 작업 패널) ·
  `/test-mgmt/test-status`(시험현황 목록 표시, 상세 서랍).
- 테이블: `qc_job_items`(검토 상태) · `qc_job_item_review_history`(배치·항목별 검토 이력) · `qc_jobs`(단계 도출·승인) ·
  `qc_job_status_history`(단계 이력) · `pct_orders`(오더 상태 동기화) · `notifications`(단계 전환 알림) ·
  `concurrent_analysis_groups`·`concurrent_analysis_group_items`(읽기만).
- 마이그레이션: **1건(0051 — 그룹 검토 DB 함수 추가, 테이블 구조 변경 없음). Supabase SQL Editor 에서 수동 적용이 필요**하며,
  적용 전에는 그룹 검토가 설치 안내와 함께 거절된다(배치 단건 검토·승인은 영향 없음).
- 확정(LOCK)·작업 시작 상태와의 관계:
  - **상태 전이·확정(승인완료)을 적용하는 단위가 바뀐다** — 한 번의 조작으로 여러 배치의 검토 상태와 승인완료가 함께 바뀐다.
    각 배치에 대한 허용 조건(항목 검토 전제, 승인은 승인전 + 전 항목 검토 완료)은 지금 규칙 그대로 배치마다 판정한다.
  - LOCK 은 일정 자동 변경 금지일 뿐이라 검토·승인과 무관하다(지금과 같다).
  - 작업을 시작하지 않은 그룹 오더는 검토·승인할 것이 없어 대상에서 빠진다.
- 크론: 영향 없음. PCT 적재(09:00/14:00)의 동시분석 그룹 재구성은 그대로이고, 그룹 조작은 **누른 시점의 그룹 구성**을 따른다.
  장비 대기 자동취소(매시 정각)와 무관하다.
- 함께 가는 규칙: 시험항목 단위 검토(2026-09-15-item-level-review)의 단계 도출·검토 전제·이력 규칙을 그대로 쓴다.

## Constraints
- **GMP/ALCOA+**: 검토 이력은 배치·시험항목마다 1행씩, 검토자·시각과 함께 남아야 한다. 그룹 조작이 "그룹 1건" 기록으로 뭉개지면 안 된다.
- 그룹 검토는 검토 기록·항목 갱신·단계 전환이 **함께 성공하거나 함께 실패**한다. DB 오류가 나면 그룹 전체가 되돌려져
  일부 배치에만 기록이 남는 일이 없어야 한다(조건 불충족으로 건너뛴 배치는 실패가 아니다).
- 검토 허용 조건·단계 도출 규칙을 **새로 한 벌 더 만들지 않는다** — 배치 단건 검토와 같은 판정을 쓴다.
- 승인은 배치마다 기존 승인 조건(승인전 + 전 항목 검토 완료)을 그대로 지킨다. 그룹이라고 조건을 느슨하게 하지 않는다.
- 검토 취소·재실시·관리자 직접 변경은 그룹으로 전파하지 않는다.
- 최종 판정은 서버가 **조작 시점의 그룹 구성**으로 한다. 화면에 보인 배치 목록은 참고일 뿐이다.
- 권한은 관리자만. 화면 버튼 숨김만으로 막지 않는다.
- 슬랙·앱 알림은 단계가 실제로 바뀐 작업마다 한 번 — 항목 수·그룹 조작 수만큼 보내지 않는다.
- 배치가 1건뿐인 그룹에는 그룹 버튼을 보이지 않는다.
- 운영 배포는 `main` push 다. SQL 0051 을 먼저 적용한 뒤 앱을 배포한다.

## Open questions
- **그룹 승인은 원자적이지 않다.** 배치마다 기존 승인 경로를 차례로 부르므로, 도중에 서버가 죽으면 앞 배치만 승인완료로
  남을 수 있다(다시 누르면 남은 배치만 처리된다). 승인까지 한 트랜잭션이어야 하는지는 운영 사용 뒤 판단한다.
- 그룹 구성이 작업 시작 뒤 적재 재구성으로 바뀌면(잠기지 않은 그룹), 관리자가 기억하는 "그 그룹"과 서버가 조작한 배치가 달라질 수 있다.
  재적재가 진행 중 오더의 그룹을 실제로 바꾸는지는 확인하지 않았다 — 결과에 처리 배치 QC번호를 보여 주는 것으로 충분한지 확인이 필요하다.
- 시험자 할 일 화면에서도 그룹 카드의 검토 진행 상황(배치별 검토 중·완료)을 묶어 보여 줘야 하는지는 이번 범위에 넣지 않았다.
- 그룹 검토 완료 뒤 전 배치가 승인전이 되면 승인까지 자동으로 넘길지(현행 규칙: 승인은 사람이 누른다)는 바꾸지 않았다.
