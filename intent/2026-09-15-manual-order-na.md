# Intent: 수동 오더 정보 표를 자동 오더와 같게 맞추고, 칸마다 N/A 로 의뢰할 수 있게 한다
Author: kyo (개발) · Status: completed
승인: 2026-09-15 사용자 사전 승인

## Problem
사용자 원문:
- T2 — "오더정보가 수동오더랑 자동 오더랑 오더정보 테이블이 서로 다르니 수동오더 또한 자동오더 테이블로 동일하게 변경"
- T3 — "수동 오더 정보에 각 항목 별 N/A 기능 필요. 제조번호, 제형등 정보가 없을때 품목이름과 종료일자로 의뢰 할 수있게 필수 필드 적용"

지금 겪는 불편:
- 관리자가 오더를 직접 추가할 때 보는 '오더 정보' 는 칸 모양·순서가 자동 오더를 고칠 때 보는 '오더 정보' 표와 다르다. 같은 오더인데 화면마다 읽는 순서가 달라 헷갈린다.
- 수동 오더에는 '구분'(밸리데이션 구분)을 넣을 방법이 화면에 없어 늘 비어 있다.
- 제조번호·제형·포장일 같은 정보가 아직 정해지지 않은 시험 의뢰(개발 시료, 임시 의뢰 등)가 있는데, 지금은 품목코드·제조번호가 필수라 가짜 값을 지어 넣어야만 등록할 수 있다.
- 가짜 값으로 등록하면 같은 가짜 값을 쓴 다른 오더와 부딪히거나, 나중에 누가 봐도 그 값이 실제 번호인지 알 수 없다.
- 반대로 끝나야 하는 날짜(완료예정일)는 지금 필수가 아니라 비워 둔 채 등록할 수 있다.

## Proposed outcome
- 오더 추가 서랍과 오더 수정 서랍의 '오더 정보' 가 같은 표 모양·같은 칸 순서로 보인다. 수동 오더도 '구분' 을 넣을 수 있다.
- 자동 오더의 식별 정보(제조팀 시트가 원본인 칸)는 지금처럼 고칠 수 없다. 수동 오더는 식별 정보를 입력·수정할 수 있다.
- 수동 오더는 **품목명과 완료예정일만 있으면** 등록된다. 이 둘이 없으면 화면과 서버 모두 거절한다.
- 품목코드·제조번호·제형·포장일·구분·착수 예정일은 칸마다 "N/A" 로 표시해 비워 둘 수 있다.
- N/A 로 둔 칸은 목록·카드·서랍·할 일·작업 현황·알림·챗봇 답변 어디에서나 "N/A" 로 보인다. 가짜 번호처럼 보이지 않는다.
- 나중에 실제 값을 알게 되면 수정 서랍에서 N/A 를 풀고 실제 값을 넣을 수 있다. 이미 있는 오더와 같은 제조번호·품목코드면 지금처럼 거절된다.
- N/A 오더가 다른 오더와 동시분석으로 잘못 묶이거나, AI 배정 결과가 다른 오더와 섞이거나, 제조팀 시트 적재가 그 오더를 덮어쓰지 않는다.
- 포장일이 N/A 인 오더는 AI 자동배정 대상이 아니라는 것이 화면과 자동배정 결과에 분명히 보인다. 수동 배정은 된다.
- 품목 마스터에 없는 오더(품목코드 N/A 등)는 오더에 시험항목을 직접 지정하면 작업을 시작할 수 있고, 막힐 때는 무엇을 하면 되는지 안내가 나온다.

## Affected users and systems
- 역할: 관리자(오더 추가·수정, 배정) · 시험자(할 일·작업 시작 화면에서 N/A 표시와 시작 안내를 본다) — 둘 다
- 화면: 오더 관리 `/schedule/orders` 의 오더 추가 서랍·오더 수정 서랍·오더 목록 카드, 시험자 할 일·작업 현황·작업 시작 흐름, 알림·슬랙 메시지, 챗봇 답변
- 테이블: `pct_orders`(수동 오더 행, 선택 칸 비움·식별 칸 대체값), `pct_order_edits`(수정 이력), `pct_order_test_items`(시험항목 지정), 간접적으로 `concurrent_groups`·`qc_jobs`·`qc_job_items`
- 확정(LOCK)·작업 시작 상태와의 관계: LOCK·작업 시작 뒤 고정되는 칸 규칙은 바꾸지 않는다. 작업이 시작된 오더는 지금처럼 식별 칸을 고칠 수 없으므로, N/A 를 실제 값으로 바꾸는 것도 작업 시작 전까지만 된다. 작업 시작 조건 중 '품목 마스터에 시험항목이 있어야 함' 은 오더에 직접 지정한 시험항목으로도 만족되게 넓힌다.
- 크론: `instrumentation.ts` 의 PCT 적재(09:00/14:00)가 수동 오더를 만난다. 적재 매칭 키(제조번호·품목코드)가 N/A 오더와 겹치지 않아야 한다. 적재 코드 자체의 변경은 이번 범위가 아니다. 장비 대기 자동취소 크론은 영향 없음.

## Constraints
- 데이터베이스 구조 변경(마이그레이션) 없이 한다. 기존 NOT NULL·유일 제약(`제조번호+품목코드`)은 그대로 둔다.
- 자동 오더(시트 적재 오더)의 등록·수정 규칙과 화면 동작은 바꾸지 않는다 — 식별 칸·구분 고정, 시트 원본 원칙 유지.
- 기존에 등록된 수동·자동 오더의 값은 건드리지 않는다. 기존 오더가 우연히 N/A 로 보이는 일이 없어야 한다.
- 사용자가 N/A 표시용 값을 직접 입력해 N/A 오더를 흉내 낼 수 없어야 한다.
- 작업 시작 뒤 일정·식별 칸 변경 금지, LOCK 존중 원칙을 깨지 않는다.
- 한국어 UI·에러 문구, 공통 날짜 입력 컴포넌트, 서랍(모달) 수정 UX, 디자인 규칙(파랑·rounded-md·최소 글자 크기)을 따른다.
- 병렬로 진행 중인 동시분석 그룹 일괄 진행 작업(T1)과 같은 화면·서비스 영역을 건드리지 않는다.

## Open questions
- 제조팀 시트 적재가 같은 제조번호·품목코드의 수동 오더를 자동 오더로 덮어써 '수동' 표시가 사라지는 기존 위험이 있다. N/A 를 실제 번호로 채운 뒤 그 번호가 시트에 올라오면 이 일이 생긴다. 이번에는 막지 않는데, 언제 어떤 규칙(수동 우선? 병합 알림?)으로 막을 것인가.
- 포장일이 N/A 인 오더를 AI 자동배정에서 계속 뺄 것인가, 완료예정일에서 거꾸로 계산해 배정 대상으로 넣을 것인가. 이번에는 빼고 안내만 한다.
- 사용자가 말한 "오더정보 테이블" 이 정말 오더 추가 서랍인가. 현재 코드의 수정 서랍은 이미 수동·자동이 같은 표라, 운영 화면이 이전 배포본이었을 가능성을 사용자에게 확인하지 못했다.
- "값을 아직 모름(미입력)" 과 "해당 없음(N/A 확인)" 을 기록으로 구분해야 하는가. 구분하려면 구조 변경이 필요해 이번엔 하지 않는다.
- 품목 마스터에 없는 품목으로 '전항목' 을 고른 수동 오더는 시험항목을 어디서 받을 것인가 — 매번 오더에 직접 지정할지, 마스터 등록을 유도할지.
- 대시보드의 '신규 품목' 집계가 수동 오더를 모두 신규 품목으로 세는데, N/A 오더도 여기에 세어야 하는가.
