# Intent: 시험자가 잘못 누른 [작업 시작]을 스스로 되돌린다
Author: kyo (개발) · Status: approved

## Problem
시험자 화면(할 일 / 관리자에게는 내 작업)에서 [작업 시작]을 누르면 오더가 곧바로 `대기 → 진행중`으로
넘어가고 QC번호가 부여된다. 장비 경고나 시험 전 확인사항이 없는 오더는 **확인 단계 없이 한 번에**
넘어가고, "선택 실행"은 여러 오더를 한꺼번에 그렇게 만든다.

잘못 누르거나 시험 준비가 안 된 상태에서 눌러도 시험자가 되돌릴 방법이 없다. 작업이 생긴 오더는
재배정·일정 변경·시험항목 변경이 막히므로, 실수 한 번이 관리자의 정정 요청과 수작업으로 이어진다.
시험항목 하나를 잘못 시작한 경우는 이미 되돌릴 수 있지만, 작업 자체의 시작은 되돌릴 수 없다.

## Proposed outcome
- 시험자는 **지금 시험항목에 시작·완료 기록이 하나도 없는 자기 작업**에 한해, 진행 중 목록에서
  [시작 취소]를 눌러 자기 작업 시작을 되돌릴 수 있다.
- 되돌리기 전에 확인 창에서 사유를 고른다(잘못 눌렀음 / 시험 준비 안 됨 / 기타 직접 입력).
  확인 창은 **내 작업 기록과 QC번호가 사라지고, 다른 담당자 작업이 없으면 오더가 시작 대기로 돌아간다**는
  사실을 분명히 알린다.
- 다른 담당자 작업이 없던 오더는 시작 대기 목록에 다시 나타나고, 준비가 되면 다시 시작할 수 있다.
  2인 배정에서 상대 담당자의 작업이 남아 있으면 오더 상태는 그대로이며, 화면이 그 사실을 알려 준다.
- 관리자는 "작업 시작 취소" 알림으로 누가 어떤 오더를 왜 되돌렸는지 알고, 오더 수정 이력에서
  취소 사실·당시 QC번호·사유와 (실제로 바뀐 경우에만) 오더 상태 변경을 나중에도 확인할 수 있다.
- 지금 시험항목에 시작·완료 기록이 있는 작업, 지연·검토 이후 단계의 작업, 남의 작업은 되돌릴 수 없고
  이유가 한국어로 안내된다.

## Affected users and systems
- 역할: **시험자**(본인 작업만 되돌림) · **관리자**(알림·이력으로 확인만. 관리자 자신의 작업은 시험자와 같은 규칙)
  - 2인 배정의 담당자2도 **자기 작업만** 되돌린다. 함께 배정된 상대의 작업은 볼 수 있어도 되돌릴 수 없다.
- 화면: `/my-tasks` (진행 중 섹션의 작업 카드, 동시분석 그룹 카드의 배치 표시) ·
  오더 화면의 수정 이력(취소 기록을 "작업 시작" 항목으로 보여 줌)
- 테이블: `qc_jobs`(작업 제거) · `qc_job_items`(작업과 함께 제거) · `pct_orders`(다른 작업이 없을 때 상태 복원) ·
  `pct_order_edits`(취소 감사 기록) · `notifications`(관리자 알림).
  `qc_job_status_history` 의 해당 작업 이력은 작업과 함께 사라진다 — 그래서 감사는 오더 수정 이력에 남긴다.
- 마이그레이션: **1건(DB 함수 추가. 테이블 구조·기존 데이터 변경 없음). Supabase SQL Editor 에서 수동 적용이 필요**하며,
  적용 전에는 시작 취소가 안내 메시지와 함께 거절된다.
- QC번호 채번: 번호가 지워진 뒤 같은 분에 다시 시작해도 기존 번호와 부딪히지 않아야 한다.
- 확정(LOCK)·작업 시작 상태와의 관계:
  - **작업 시작 상태의 역방향 전이(진행중 → 대기)를 새로 허용한다** — 상태 전이 규칙 변경이다.
  - **LOCK(확정)은 유지된다.** LOCK 된 오더도 되돌릴 수 있고, LOCK 값은 바뀌지 않는다.
    LOCK 은 일정 자동 변경 금지이지 실행 금지가 아니다.
  - **작업이 있어서 걸리던 수정 제한(재배정·일정 변경·시험항목 변경)은 그 오더의 작업이 모두 없어졌을 때만 풀린다.**
    2인 배정에서 함께 배정된 담당자의 작업이 남아 있으면 제한도 그대로 남는다. 다만 LOCK 이 켜진 오더라면 LOCK 에 따른 제한은 그대로 남는다.
  - 담당자·예정 기간·오더 시험항목 스냅샷·동시분석 그룹·장비 예약은 바뀌지 않는다.
  - 동시분석 그룹의 배치 하나를 되돌려도 같은 그룹의 다른 배치는 영향받지 않는다.
- 크론: 직접 바꾸지 않는다. 다만 되돌린 오더가 `대기` 이고 LOCK 이 꺼져 있으면, 09:00/14:00 PCT 적재가
  이 오더를 다시 자동 갱신 대상으로 본다(시작 전과 같은 상태로 돌아가는 것이므로 의도된 결과로 본다).
  장비 대기 자동취소(매시 정각)와는 무관하다.

## Constraints
- 새 작업 상태값을 만들지 않는다.
- 감사 기록이 남지 않으면 되돌리기도 일어나지 않아야 하고, 되돌리기가 일어나지 않았으면 감사 기록도 남지 않아야 한다
  (GMP/ALCOA+). 감사 기록은 **실제로 일어난 일만** 적는다. QC번호는 재사용될 수 있으므로 당시 QC번호를 반드시 남긴다.
- 최종 허용 판정은 서버가 한다. 화면의 버튼 숨김만으로 막지 않는다.
- 작업 시작 동작(QC번호 채번 충돌 방지 외), 시험항목 단위 시작 취소 동작은 바꾸지 않는다.
- 이미 수행한 시험 기록(시작·완료 시각·소요시간)은 **어떤 경우에도, 동시에 들어온 요청이 있어도** 지우지 않는다 —
  그래서 한 항목이라도 실행 흔적이 있으면 거절한다.
- 기존 "작업 시작" 알림은 지우지 않는다. 취소 알림과 짝을 이뤄 정정 사건으로 남긴다.
- 이미 발송된 슬랙 메시지·과거에 내보낸 리포트는 되돌리지 못한다.

## Open questions
- **관리자 대리 취소**를 열 것인가? 지금은 본인만 되돌린다. 시험자가 자리를 비운 사이 관리자가 대신
  되돌려야 하는 상황이 실제로 생기는지 운영에서 확인이 필요하다.
- **지연 상태의 작업**도 되돌리게 할 것인가? 되돌리면 납기 경과 표시가 사라지고 시작 대기 목록 노출 기준(대기만)도
  함께 정해야 해서 이번에는 거절한다.
- **항목 시작을 개별 취소한 뒤** 작업까지 되돌리는 경우를 허용할 것인가? 항목 시작 취소는 흔적을 남기지 않아
  "한 번도 시험하지 않았음"을 증명할 수 없다. 이번에는 "지금 실행 흔적 없음"을 기준으로 허용한다.
- 되돌린 오더를 **재배정·일정 변경·자동 적재가 다시 건드려도 되는가**? 작업이 사라져 수정 제한이 풀리는 것을
  의도로 보았지만, 관리자가 실제로 이를 원하는지는 확인하지 못했다.
- 취소 알림 생성이 실패했을 때 **다시 보내는 경로**가 필요한가? 지금은 시험자 화면에 경고만 보여 준다.
- 되돌린 뒤 슬랙에도 정정 메시지를 보낼 것인가? 지금은 앱 내 관리자 알림만 남긴다.
