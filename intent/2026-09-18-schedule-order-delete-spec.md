# 삭제 오더 재적재 방지 규칙
Author: 사용자 요청/오케스트레이션 · Status: completed

## 사용자 삭제와 적재 삭제의 구분

사용자가 삭제한 오더는 `pct_orders`의 소프트 삭제 상태를 유지하면서 사용자 삭제 표식을 별도로 보존한다. 제조팀 시트에서 사라져 적재 로직이 삭제한 오더는 기존 적재 삭제 흐름을 따르며, 사용자 삭제 표식이 있는 오더만 자연키 재등장 시 복구 대상에서 제외한다.

## 복구 판정

`pctIngest`는 삭제 상태 행을 자연키로 읽어 중복을 피하되, 사용자 삭제 표식이 있으면 복구 분기와 담당자·LOCK 초기화를 수행하지 않는다. 이 규칙은 0056 마이그레이션으로 기존 `pct_orders` 행에 저장할 수 있어야 하며, 소프트 삭제 행과 수정 이력은 보존한다.

## 부분 성공

선택된 각 오더는 동일한 삭제 사유로 독립적으로 기존 삭제 규칙을 검사한다. 이미 삭제됨·LOCK·`qc_jobs` 존재 등의 차단 사유는 결과에 남기고, 처리 가능한 행만 성공시킨다.

## 배포 순서 및 적재 재등장 방지

0056이 적용된 DB에서는 자동 오더 삭제 표식을 저장해 동일 자연키의 다음 적재 복구를 막는다. 0056 미적용 DB에서는 수동 오더 삭제만 허용하고 자동 오더 삭제는 "데이터베이스 업데이트 0056을 먼저 적용"하라는 명확한 안내로 차단한다. 운영은 0056 선적용 후 앱 배포 순서를 따른다.
