# 지연 사유·시험자 운영 성과 기록 규칙
Author: 사용자 요청/오케스트레이션 · Status: completed

## Problem
지연·복귀 전이에 분류와 사유가 없어 운영 원인을 구분할 수 없고, 기존 상태 이력만으로는 통제 밖 요인과 시험자 입력을 함께 읽을 수 없다.

## Proposed outcome
지연 진입과 복귀 모두 고정 분류와 2자 이상 사유를 남긴다. 분류의 기본 attribution은 코드가 정하고 관리자는 건별로 확인·수정할 수 있으며, 기존 note 표시와 상태 이력은 유지한다.

## Affected users and systems
- 역할: 관리자 / 시험자 모두. 시험자는 본인 작업의 지연·복귀를 기록하고, 관리자는 상태 이력과 분류를 열람·수정한다.
- 화면: `/my-tasks`, 시험현황 상세의 상태 이력.
- 테이블: `qc_job_status_history`, `delay_reason_categories`.
- 확정(LOCK)·작업 시작 상태와의 관계: 기존 상태 전이와 LOCK 규칙은 유지하며, 지연·복귀 전이의 사유 검증만 추가한다.
- 크론: `instrumentation.ts`의 기존 크론과 자동 지연 판정에는 영향이 없다.

## Constraints
- 분류 목록은 코드 상수와 SQL 시드로 고정하며 설정 화면·CRUD는 만들지 않는다.
- 분류 또는 사유(2자 이상)가 없으면 전이를 거절한다. 일괄 변경은 한 번 입력한 값을 건별로 적용하고, 일부 실패 시 성공 건은 유지하며 실패 건과 원인을 사용자에게 알린다.
- 0058 미적용 환경에서는 지연·복귀 전이를 실행하지 않고 SQL Editor 적용 안내를 한국어로 반환한다. 기존 상태 이력의 note 렌더링은 깨지지 않는다.
- attribution은 분류 기본값으로 저장하고, 관리자는 해당 이력 건의 attribution을 수정할 수 있으며 변경 이력은 상태 이력의 별도 system 행으로 남긴다.
- 연말 보고서는 시험자 본인이 자기 지표와 팀 평균만, 관리자는 전원을 조회한다. 타 시험자의 개별 지표는 노출하지 않는다.
