# Intent: 시험 진행 중에 시험항목 담당자를 같은 그룹 안에서 바꾼다
Author: kyo (개발) · Status: completed
승인: 2026-09-15 사용자 사전 승인(오케스트레이션 작업 지시)

## Problem
사용자 요청 원문:
> 시험이 진행 중일때 시험항목 담당자가 변경되면 해당 시험항목도 변경 할 수 있도록 기능을 만들어줘.
> 다만 그 시험항목 변경은 같은 그룹에 있는 사람만 가능하도록 해줘야해.

한 오더를 여러 담당자가 나눠 맡을 때, 어느 시험항목을 누가 할지는 **작업을 시작하기 전에만** 정할 수 있다.
담당자 중 한 명이라도 [작업 시작]을 누르면 그 오더의 시험항목 배분이 통째로 잠긴다.

- 시험 도중 한 담당자가 장비·일정·휴가 사정으로 남은 시험항목을 동료에게 넘겨야 해도 시스템에서 옮길 방법이 없다.
- 지금 가능한 우회로는 "담당자가 작업 시작을 취소 → 관리자가 다시 배분 → 다시 시작" 뿐인데, 시험항목을 하나라도 시작·완료했으면 이 길도 막힌다.
- 그래서 실제로는 B 가 시험했는데 기록상 A 의 체크리스트에 남거나, 같은 항목이 두 사람에게 중복으로 잡히는 어긋남이 생길 수 있다.
- 지금 남는 배분 변경 이력은 "담당자1 → 담당자2" 같은 번호뿐이라, 담당자가 바뀌고 나면 실제로 누구에게서 누구에게 넘어갔는지 되짚을 수 없다.

## Proposed outcome
- 시험이 진행 중인 오더에서 **아직 손대지 않은**(시작·완료 기록도 검토 기록도 없는) 시험항목을, 그 오더에 **병렬 배정된 다른 담당자**에게 넘길 수 있다.
  - "같은 그룹" = 그 오더에 함께 병렬 배정된 담당자들이다. 그룹 밖 사람에게는 넘길 수 없다.
- **관리자**는 오더 수정 화면의 시험항목 배분에서, 작업 시작 뒤에도 흔적 없는 항목의 담당자를 그룹원 중에서 바꾼다.
- **시험자**는 할 일 화면에서 자기 몫의 흔적 없는 시험항목을 "넘기기"로 그룹원에게 넘긴다(받는 사람과 사유를 고른다).
  남의 항목을 가져오는 것은 할 수 없다.
- 받는 사람이 이미 작업을 진행 중이면 그 항목이 그 사람의 체크리스트에 바로 들어가고, 아직 시작 전이면 그 사람이 [작업 시작]할 때 포함된다.
- 넘긴 뒤 두 사람의 작업 단계와 오더 상태가 새 배분에 맞게 다시 맞춰진다(예: 넘긴 쪽의 남은 항목이 모두 끝나 있었다면 검토전으로).
- 진행 중이거나 완료된 항목, 받는 사람의 작업이 승인전 이후인 경우, 넘기면 넘기는 쪽에 항목이 하나도 안 남는 경우는 거절되고 이유가 한국어로 안내된다.
- 오더 수정 이력에 **항목명·보낸 사람·받는 사람(이름과 QC번호)·사유**가 남는다.

## Affected users and systems
- 역할: **관리자**(그룹원 사이 항목 이동) · **시험자**(자기 흔적 없는 항목을 그룹원에게 넘기기만). 둘 다.
- 화면: `/schedule/orders`(오더 수정 서랍의 시험항목 배분 섹션, 수정 이력의 "항목 담당자") · `/my-tasks`(항목 행의 넘기기 메뉴와 모달).
  넘긴 결과는 `/product-test/prod-status`·`/schedule/monthly` 등 담당자별 항목 표시에 그대로 반영된다.
- 테이블: `qc_job_items`(항목의 소속 작업 이동 또는 제거) · `pct_order_test_items`(항목 담당 번호) · `qc_jobs`(두 작업의 단계 재도출) ·
  `qc_job_status_history`(단계가 바뀐 경우) · `pct_orders`(오더 상태 동기화) · `pct_order_edits`(감사) · 병렬 배정 담당자 테이블(그룹 판정, 읽기만).
- 마이그레이션: **1건(0050 — DB 함수 추가. 테이블 구조·기존 데이터 변경 없음). Supabase SQL Editor 에서 수동 적용이 필요**하며,
  시험항목 단위 검토(0048)·병렬 배정(0049)이 먼저 적용돼 있어야 한다. 적용 전에는 항목 넘기기가 안내 메시지와 함께 거절된다.
- 확정(LOCK)·작업 시작 상태와의 관계:
  - **"작업이 하나라도 시작되면 항목 배분 변경 금지" 규칙을 항목 단위로 푼다** — 흔적 없는 항목에 한해 그룹원 사이 이동을 허용한다.
    작업 시작 뒤 배분을 한꺼번에 옮기는 것은 계속 금지다.
  - **LOCK 오더에서도 허용한다.** LOCK 은 일정 자동 변경 금지이지 실행 금지가 아니며, 담당자 구성·일정은 바뀌지 않는다.
  - 받는 사람의 작업을 대신 만들지 않는다(QC번호 채번·작업 시작 시각은 본인이 [작업 시작]할 때만 생긴다).
  - 작업 단계 재도출은 시험항목 단위 검토의 규칙을 그대로 쓴다. 이 기능만의 단계 규칙을 따로 두지 않는다.
- 크론: 영향 없음. PCT 적재(09:00/14:00)는 진행 상태 오더를 자동 갱신하지 않고 항목 배분을 건드리지 않는다. 장비 대기 자동취소(매시 정각)와 무관하다.
- 함께 가는 변경: 병렬 배정(2026-09-15-parallel-assignment — "같은 그룹"의 기준), 시험항목 단위 검토(2026-09-15-item-level-review — 단계 재도출).

## Constraints
- **이미 수행한 시험 기록은 옮기지 않는다.** 시작·완료 시각·소요시간·검토 기록이 있는 항목은 어떤 경우에도 넘기지 않는다
  (넘기면 A 의 실적이 B 의 실적으로 집계된다). 진행 중 항목은 먼저 시작을 취소해야 한다.
- 오더의 항목 배분과 실제 체크리스트가 **어긋나는 순간이 없어야** 한다. 이동·배분 갱신·감사 기록·단계 재도출은 함께 성공하거나 함께 실패한다.
- 한 항목이 두 사람의 체크리스트에 동시에 있거나, 아무의 체크리스트에도 없는 채로 시험이 끝나는 상태를 만들면 안 된다.
- 감사 기록은 **사람 이름과 QC번호**로 남긴다(번호 라벨만으로는 담당자가 바뀐 뒤 추적이 끊긴다). 사유는 필수다(GMP/ALCOA+).
- 오더 담당자 재배정 통계에 섞지 않는다(항목 이동으로 재배정 건수가 부풀면 안 된다).
- 최종 허용 판정은 서버가 한다. 화면의 메뉴 숨김만으로 막지 않는다.
- 작업 시작·작업 시작 취소·시험항목 시작/완료의 기존 동작은 바꾸지 않는다.
- 운영 배포는 `main` push 다. 통합 전에는 `main` 에 올리지 않고, SQL 0048 → 0049 → 0050 적용 뒤 앱을 배포한다.
